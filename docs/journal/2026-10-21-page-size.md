# 2026-10-21: Data pages of 1 MiB, not 20,000 rows

genson-core's Parquet writer (genson-core/src/parquet.rs, `open_writer`) lifts arrow-rs's
data page row limit (`set_data_page_row_count_limit(usize::MAX)`), so a data page ends
at arrow-rs's page size limit of 1 MiB alone, as Polars' pages do. Before, a page also
ended every 20,000 rows (arrow-rs's `DEFAULT_DATA_PAGE_ROW_COUNT_LIMIT`). Scripts and
logs are in `2026-10-21-page-size/`. The writer-only benchmark is the one of
`2026-10-21-adaptive-dictionary/threshold-sweep/` (`duel.rs`, the same tables).

## Why

On the flat tables both writers write every column plain, yet Polars' files were
smaller: the Int64 column of the 2-column table was 21.4 MB from genson and 17.5 MB from
Polars. Every page of both files (`pagedump.rs`, summarised by `pages.py`;
`logs/layout_flat_2.txt`) shows where the difference is:

| writer | column | data pages | values per page | uncompressed per page | uncompressed | compressed | ratio |
|---|---|---|---|---|---|---|---|
| genson, 20,000 rows | `c1` (Int64) | 626 | 20,000 | 160 kB | 100.01 MB | 21.39 MB | 4.67 |
| Polars | `c1` | 119 | 116,508 | 932 kB | 100.00 MB | 17.46 MB | 5.73 |
| genson, 1 MiB | `c1` | 92 | 131,072 | 1,049 kB | 100.00 MB | 17.34 MB | 5.77 |
| genson, 20,000 rows | `c0` (string) | 626 | 20,000 | 258 kB | 161.12 MB | 46.16 MB | 3.49 |
| Polars | `c0` | 214 | 61,680 | 795 kB | 161.11 MB | 45.14 MB | 3.57 |
| genson, 1 MiB | `c0` | 145 | 81,356 | 1,049 kB | 161.11 MB | 45.03 MB | 3.58 |

- **Same everywhere but the pages:** both files have data page v1, PLAIN values,
  RLE definition levels, zstd level 1, chunk statistics and a page index. The
  uncompressed bytes are the same; only the page boundaries differ.
- **Small pages compress worse:** zstd compresses each page on its own, so a page of
  20,000 Int64 values (160 kB) compresses to a ratio of 4.67, and a page of 1 MiB to
  5.77.
- **The row limit is the cause:** with it lifted, the same writer's pages fill to 1 MiB
  and the column comes out 17.34 MB, under Polars'. Writing with the limit set
  explicitly to 20,000 gives the old file byte for byte.

## Measured

- **Variants:** pages of 20,000 rows (the parent), pages of 1 MiB with no row limit, and
  pages of 2 MiB with no row limit, each set from the environment in a scratch build of
  the parent (`logs/page_limits_from_env.diff`), against Polars 0.55.2's sink. "No row
  limit" was set as a limit of 2^62 rows. The change sets `usize::MAX`, and no page
  reaches either.
- **Setup:** the writer alone, zstd 1, row groups of 1Mi rows. 5 rounds of fresh
  processes in rotated order, after a warm-up (`pagesweep.py`).
- **Results** (`logs/pagesweep.txt`; median user CPU and wall time in seconds; file size in
  MB; `logs/page_verdicts.txt` judges by disjoint ranges):

| table | user CPU: 20k / 1 MiB / Polars | wall: 20k / 1 MiB / Polars | MB: 20k / 1 MiB / 2 MiB / Polars |
|---|---|---|---|
| flat, 2 columns, 12.5M rows | 1.15 / 1.21 / 1.48 | 0.41 / 0.39 / 0.56 | 67.60 / 62.38 / 61.90 / 62.62 |
| flat, 94 columns | 1.12 / 1.18 / 1.34 | 0.47 / 0.55 / 0.45 | 60.16 / 58.34 / 57.88 / 58.67 |
| graded_tall | 1.96 / 1.84 / 2.30 | 1.01 / 0.77 / 0.80 | 78.71 / 77.13 / 76.69 / 70.12 |
| graded_wide | 2.06 / 2.14 / 2.45 | 1.06 / 0.79 / 0.82 | 83.80 / 83.21 / 82.94 / 81.73 |
| `List(String)` | 1.72 / 1.67 / 2.07 | 0.76 / 0.87 / 2.93 | 80.40 / 80.40 / 80.54 / 80.32 |
| `List(Struct)` | 2.41 / 2.41 / 4.65 | 1.15 / 1.04 / 4.96 | 113.34 / 113.34 / 112.68 / 113.36 |
| claims (chunk 0) | 2.87 / 3.18 / 22.62 | 1.50 / 1.04 / 25.20 | 54.08 / 54.08 / 53.90 / 59.02 |
| labels | 0.08 / 0.08 / 0.14 | 0.07 / 0.06 / 0.14 | 4.14 / 4.14 / 4.13 / 4.36 |
| descriptions | 0.05 / 0.07 / 0.08 | 0.05 / 0.06 / 0.16 | 4.48 / 4.48 / 4.46 / 4.60 |
| aliases | 0.03 / 0.03 / 0.03 | 0.03 / 0.03 / 0.04 | 1.80 / 1.80 / 1.80 / 1.75 |

- **Time:** 1 MiB pages are within noise of 20,000-row pages on every table, in user CPU
  and wall time.
- **Size:** the flat tables are 7.7% and 3.0% smaller, under Polars' on both, and the
  graded tables 2.0% and 0.7% smaller. The nested and Wikidata tables are unchanged byte
  for byte. Their pages already reached 1 MiB before 20,000 rows, or the tables have
  fewer rows than that.
- **2 MiB pages:** they shrink the files by up to 0.8% more. They were slower on the
  2-column table (1.30 s of user CPU, 0.50 s wall), and readers handle pages of twice
  Polars' size. 1 MiB is kept.
- **Against Polars (corrected):** the Polars column above is Polars 0.55.2 built from
  crates inside the benchmark binary. That build is much slower than the official Polars
  2.0.0 wheel: at the same row groups the wheel writes `List(String)` in 1.23 s, against
  the crate build's 2.93 s. The column holds for file sizes, not for time.
  - **The rerun:** the #288 journal's grid harness was run against the official wheel
    (`sink_parquet`, zstd 1, its default row groups), 5 rounds of fresh processes, and 10
    for the 1-column, 2-column and 94-column tables.
  - **Result, with 1 MiB pages:** Polars is faster on the flat tables, 1.2–1.55× (for
    example 0.38 s against 0.59 s on 2 columns), and on `List(String)` (0.71 against
    1.13 s). The two are level on `List(Struct)` (1.55 against 1.59 s). genson is 23×
    faster on claims (0.88 against 20.0 s).

## Correctness

- **Decoding:** every output of the 1 MiB variant equals its input (pyarrow
  `Table.equals`, same Arrow schema; `check.py` of the threshold sweep).
- **Unchanged layout (flat and graded tables):** each output has the same Parquet schema,
  Arrow schema, key-value metadata, row groups, rows per row group and encodings per
  column as the parent's, and the same rows. The nested and Wikidata outputs are
  byte-identical to the parent's.
- **Test:** `test_flat_pages_end_at_the_page_size_limit` (genson-core/src/tests/
  parquet.rs) writes 300,000 distinct Int64 values. It checks by the offset index that
  they take three pages of more than 20,000 rows each, and that they read back unchanged.
  Without the change it sees fifteen pages of 20,000 and fails.

## Current State

- `open_writer` sets `set_data_page_row_count_limit(usize::MAX)` beside zstd 1, the list
  and map names, and the dictionary decision.
- Page statistics and the offset index are written as before, one entry per page, so a
  reader that skips pages by them skips in steps of up to 1 MiB (Polars' granularity)
  rather than 20,000 rows.

## Missing

- **The graded tables are still larger than Polars'** (77.13 against 70.12 MB, and
  83.21 against 81.73). The cause is the dictionary decision, not the pages: Polars
  dictionary-encodes columns that repeat across the whole chunk and look distinct in a
  16,384-value sample (`2026-10-21-adaptive-dictionary.md`, The threshold).
- **Aliases:** genson's file is 1.80 MB to Polars' 1.75.
- **Time against the official Polars wheel:** genson is slower on flat tables and
  `List(String)` (above, "Against Polars (corrected)").
