# Prune: drop the records holding named fields during normalisation

## Current State

- wikidata-pq `fd4385e` ("fix: quarantine claims snaks on deleted properties") removes snaks on deleted properties (P450, P4003) from the claims in Polars, after `normalise_from_parquet`:
  - `quarantine_snaks` explodes the claims down to single snaks to record the bad ones;
  - `drop_quarantined` rebuilds the claims column with nested `list.eval` / `list.filter`.
- Profiled on `chunk_200` (70 MB source) with wikidata-pq `scripts/profile_chunk.py`, one run of 13.06 s:
  - `quarantine_snaks` 5.95 s;
  - `drop_quarantined` about 2.8 s (the `with_columns` in `normalise_claims_direct`);
  - `normalise_from_parquet` 2.36 s over all four calls.
- The two steps run on every chunk. 6 of the first 190 chunks (0, 12, 16, 30, 67, 84) had a bad snak, 7 snaks in all.
- No timing was taken before or after `fd4385e`, and no performance requirement was set for it.
- The bad snaks, as they appear in the inferred claims schema (wikidata-pq `QUARANTINE_FIELDS`, `RAW_DV_SCHEMA`):
  - `mainsnak__string`: the mainsnak is the bare property id, promoted by `force_scalar_promotion` (Q1401203, P450, `chunk_16`);
  - `datavalue.value` and `datavalue.error`: the datavalue is an error message (six qualifier snaks on P450, under P375 and P793);
  - `value__string`: a qualifier or reference snak that is the bare property id, wrapped by `wrap_scalars` (none seen).
- genson names a promoted or wrapped scalar `{field}__{type}` (`make_promoted_scalar_key`, genson-core/src/schema/core.rs), in `normalise_value` (genson-core/src/normalise.rs:291) and during map inference. The name depends on the inferred schema, e.g. the `value` in `value__string` is the value of a map entry.
- In the kv map encoding, a map entry's `value` is created at output and is not a record field of the schema.
- No raw row of the 7 bad snaks is kept as a test fixture in wikidata-pq or polars-genson.

## Design

One option, `prune: set[str]`, with `prune_output_path` for what it removes (like `extract_invariants` with `lookup_output_path`).

- Names are record field names of the inferred schema, at any depth, the same way `force_field_types` and `force_scalar_promotion` name fields. A promoted scalar goes by its promoted name (`mainsnak__string`).
- The named fields are removed from the schema.
- During normalisation, a record holding a non-null value for a named field is pruned. The schema is known there, so records are told apart from maps.
- A pruned value that is a record's field takes that record with it: the record is incomplete without it. This repeats up the tree until the pruned value is an array element or a map entry, which is removed on its own.
- An array, map or record left empty by pruning is removed in the same way. A value that was already empty is left as it was.
- If pruning reaches the row's root, the row's value is null.
- Each pruned value is written to `prune_output_path`: the `keep_columns`, the path of keys and indices from the root to the value, and the value as JSON.

For the Wikidata claims, `prune={"mainsnak__string", "value__string", "value", "error"}` (the fields wikidata-pq's `is_quarantined` tests):

- a mainsnak holding `mainsnak__string`, or whose datavalue holds `value` or `error`, is pruned with its statement;
- a qualifier or reference snak like that is pruned from its list;
- a qualifier group or reference left empty is removed.

This matches the "Snaks on deleted properties" section of the claims dataset card. The inferred claims schema is then `claims_schema`, and wikidata-pq can delete `RAW_DV_SCHEMA`, `RAW_SNAK_SCHEMA`, `QUARANTINE_FIELDS`, `raw_claims_schema`, `is_quarantined`, `quarantine_snaks` and `drop_quarantined`.

## Success criteria

- Performance: with `prune` set, the wikidata-pq claims step on `chunk_200` and `chunk_3` is within 5% of its time at `fd4385e^`. Measured with `scripts/profile_chunk.py` on the same machine, before and after.
- Correctness: on chunks 0, 12, 16, 30, 67 and 84, the claims match the output of `fd4385e`, and the pruned values give the same 7 `(id, claim, part, key, snak)` rows as `quarantine/`.
- Schema: the claims schema inferred with `prune` set equals `claims_schema`.

## Fixtures

- The raw rows (`id`, `claims`) of the 6 entities with bad snaks (Q14942, Q1064394, Q1401203, Q2580456, Q6116054, Q7669867), taken from the source chunks, are kept as a Parquet fixture in polars-genson-py/tests/data.
- genson-core unit tests on small JSON rows, one per case:
  - a field holding a promoted scalar (bare mainsnak), pruned with its record;
  - a record holding a named field inside a list (qualifier snak);
  - the same two lists down (reference snak);
  - a scalar wrapped in a list of records (`value__string`);
  - the cascade of emptied lists, maps and records;
  - a value empty in the source, kept;
  - a map whose entries are not pruned by a named field of the same name as the kv `value`.
